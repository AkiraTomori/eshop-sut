# EMS Usability Study — Task Scenario

## Study Context

| Field | Value |
|---|---|
| Scenario | B — Event attendee journey |
| Screens exercised | B1 Events List / Discovery; B2 Event Detail; B4 Registration Confirmation / QR Code |
| Participant profile | University students unfamiliar with EMS |
| SUT | EMS — <https://prod-dev.ems-fitus.cloud/> |
| Test objective | Evaluate whether a first-time user can discover an event, register, and retrieve the check-in QR code without guidance |

## Moderator Setup

Before the participant arrives:

- Choose one upcoming event that is open for registration and safe to use for testing.
- Record its name privately in the session notes; do not reveal where it appears or how to reach it.
- Start the participant from the EMS Events page (B1) in a clean browser session.
- Confirm that the participant has a test-capable account and that registering will not consume a scarce or paid place.
- Prepare a stopwatch and the observation form.
- If recording, obtain explicit consent before starting.

## Introduction to Read Aloud

> Thank you for helping with this study. We are testing the EMS product, not you, so there are no wrong answers. Please work as you normally would and think aloud: tell me what you are looking for, what you expect to happen, and anything that feels clear or confusing. I will mostly remain quiet. You may stop at any time.

## Task to Read Aloud

Replace `[EVENT NAME]` with the selected event name before the session.

> You recently heard that **Summer School about A.I Agentic** is coming up on campus and you would like to attend. Using EMS, find the event, register for it, and show me the QR code you would use to check in.

Do not provide menu names, button labels, page locations, or a sequence of actions.

## Start and End Rules

- Start the stopwatch immediately after reading the task and saying, “You may begin.”
- Stop it when the participant displays the correct check-in QR code, explicitly gives up, or reaches the 10-minute limit.
- If the participant asks what to click, respond once with: “Please do what you would normally try.”
- Intervene only for safety, privacy, a system outage, or after the participant is completely stuck for 60 seconds. Record every intervention.
- Do not treat moderator help as an unassisted completion.

## Completion Criteria

| Outcome | Operational definition |
|---|---|
| Completed ✅ | The participant independently finds the named event, completes registration, and displays the correct QR code within 10 minutes. |
| Partial ⚠️ | The participant completes at least one major stage but does not display the correct QR code, or reaches it only after direct moderator guidance. |
| Failed ❌ | The participant cannot find the event, cannot register, gives up, times out, or reaches an incorrect end state. |

## Screen Checkpoints for the Observer

These checkpoints are for observation only and must not be shown as instructions:

| Screen | Observable milestone |
|---|---|
| B1 — Events List / Discovery | Participant identifies and opens the intended event. |
| B2 — Event Detail | Participant understands the event information and initiates registration. |
| B4 — Registration Confirmation / QR Code | Participant recognises successful registration and displays the QR code. |
