## 2. Gap Analysis

### POOL A — FR-06: Product Detail View (Web Frontend)
- When working with the A.I Agent in requirement analysis, EP and BVA, I found that the A.I Agent has a great ability to support in creating test cases based on the defined requirements. However, there are still some gaps that need to be improved:
- The A.I Agent currently creates test cases based on two available specification documents: SRS and API Documentation. However, for test cases that have a bias towards UI, the A.I Agent may not be able to generate them effectively because it is based on specification documents and lacks the ability to directly analyze the user interface. During the work process, I found a test case that the A.I has completely generated is a test case related to displaying detailed product names in the product list. In the Happy Path, this test case performs well, but if an attacker uses XSS Injection technique to inject malicious code into the product name, the A.I Agent will not be able to detect it.
- The lesson learned when working with the A.I Agent is that besides having knowledge about the domain business and UI/UX, I need to be able to identify test cases that the A.I Agent cannot generate. Additionally, I also need knowledge about security to identify security-related test cases that the A.I Agent cannot generate.
- Moreover, when working with any feature, it is necessary to accompany it with very specific common rules of FR21-24 to ensure that not only this feature but also other features must comply with these common rules. The document alone is not enough; it requires me to have certain understanding of some rules for protecting users, protecting user data, and protecting user information. If I don't have this knowledge, then the A.I Agent will not be able to generate test cases related to security.

### POOL B — FR-08: Checkout (Web Frontend)
- For this checkout feature, there is a test case that I noticed but the A.I did not generate, which is the test case when users try to manually adjust the total payment amount. This scenario means that when users attempt to manually change the payment amount, I expect the A.I to generate this test case, but it did not. When I executed this test case, I found that the system does not have a mechanism to protect users from manually changing the payment amount. This is a security vulnerability that the A.I did not detect.
- The lesson learned here is that besides having API test cases, I should also have UI/UX test cases to be able to detect security vulnerabilities that the A.I does not detect. I need to provide more specific information to generate additional test cases related to system security to ensure that the system has mechanisms to protect users from intentional actions of changing the payment amount. I also realized that the A.I cannot detect these security vulnerabilities, so I need to have knowledge about security to be able to identify these vulnerabilities that the A.I does not detect.

## POOL C — FR-15: Product Management (Product CRUD Web Admin)
- For this product management feature, this can be said to be one of the most complex and important features in this assignment for me to perform the testing process. The number of test cases for this feature generated by the A.I Agent is very large and completely covers all 4 API CRUD operations of this feature. If there was no support from the A.I Agent, I would not be able to complete this feature, and manual work would become very difficult and time-consuming.
- The issue I want to discuss is when the A.I Agent generates test cases for this feature, it completely overlooks test scenarios related to input fields. The scenario I want to highlight is the UI crash when users or attackers try to enter more than 1000 characters into the Description field. The A.I Agent generates test cases related to blocking on the UI and API side, but it overlooks this UI crash scenario, leading to a horizontal scroll bar appearing. This is a security vulnerability that the A.I Agent does not detect. When I executed this test case, I found that the system has no mechanism to protect users from intentionally entering too many characters into the Description field, which leads to a UI crash. This is a security vulnerability that the A.I Agent does not detect.
- Besides, the A.I Agent also inadvertently added 3 test cases related to searching for product names that are not included in the requirements of FR15 but are present in the API Documentation. However, when executing these test cases, I was unable to do so because the Search feature in FR15 does not exist, leading me to mark these test cases as Not Run along with the reason why.
- The lesson learned here is that in addition to generating test cases related to UI and API such as load issues or limit regulations, GUI or Usability issues will be extremely important if we want to have a complete system with responsive design. In other words, documentation from BA and Developer is one thing; we need certain knowledge and business domain understanding to identify test cases that the A.I Agent cannot generate if the documentation does not detail these aspects.

## POOL D — FR-04: Personal Profile Management (Mobile App)
- For this case, the A.I Agent also did not generate test cases related to observing UI/UX when users or attackers intentionally inject data with lengths up to 255 or 1000+ characters to check if the feature is correctly implemented. However, when the data is displayed on the UI, it may cause interface crashes leading to horizontal scroll bars appearing. Fortunately, on the mobile UI for users, there are no bugs related to UI crashes; when users or attackers enter long text, the input fields have vertical scroll bars, so no horizontal scroll bars appear in the application.
- The lesson learned here when working with the A.I Agent is that in addition to having API-related test cases, I also need UI/UX-related test cases to detect security vulnerabilities that the A.I does not detect. I need to provide more specific information to generate additional test cases related to system security to ensure that the system has mechanisms to protect users from intentional actions of entering excessively long data that could crash the interface.

## 3. Summary
- Overall, the A.I Agent has a great ability to support in creating test cases based on the defined requirements. However, the A.I Agent still has some limitations in generating test cases related to UI/UX and security that require human intervention to identify security vulnerabilities that the A.I does not detect. Therefore, combining the A.I with human expertise is very important to ensure that the system is thoroughly tested and secure.
